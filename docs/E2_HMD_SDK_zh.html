概览：两库分工与加载

SDK 拆成两个可 dlopen 的共享库，各导出单个符号填充版本化 vtable。应用通常只链接 sxr_recorder.h；HAL 由 recorder 在内部加载，应用一般感知不到。

加载路径

  • recorder：sxr_recorder.h 内联加载器先试 /customer/sd/libsxr_recorder.so，再试 /customer/sample_code/lib/。找不到返回 NULL。
  • HAL：hal_loader.cpp 先按裸名 libsxr_hal.so（需 LD_LIBRARY_PATH），再试 /customer/sd/、/customer/sample_code/lib/。HAL 集成在 ROM，开发者无需接触 / push，经 loader 兜底路径自动命中。
ℹ️

HAL 必须 RTLD_GLOBAL 加载。 libsxr_hal.so 会拉入底层的 libmi_*.so， 它们在 app 直链时是全局作用域；若 RTLD_LOCAL dlopen，MI 库之间的符号互解会失败 （"can't resolve symbol"）。recorder 侧 MI-free，无符号冲突风险。

HAL 自带 RPATH /config/lib，其 MI 依赖（位于 /config/lib）自定位。 app 侧只需 LD_LIBRARY_PATH=/customer/sd（recorder + HAL 所在目录）。

最小工作流

推荐用法：只用 libsxr_recorder，全部参数走库内默认。整个录制会话是单例：

⚠️

record_start 是异步的。 返回 0 只代表已入队；真正开始落盘要等 SXR_REC_EVT_STARTED 事件（两眼都抓到强制 IDR 后派发）。不等就立即 record_stop 会得到空文件。IDR_TIMEOUT / WRITE_ERROR 事件会自动收尾本段。

API 详解

libsxr_recorder — 5 个 API（v2 vtable）

函数作用返回
record_init(preview_cb, userdata) 单例初始化：内部构建 stereo 管线 + 起 IMU/磁线程；给 preview_cb 则同时起子码流取帧。可反复 init/deinit 0 成功；−1 失败（未初始化）
record_deinit() 收尾：finalize 仍活动的录制段 → 停预览分发/传感器线程 → 拆管线。幂等 —
record_start(dir, evt_cb, userdata) 异步开始一段录制：建 <dir>/Camera{0,1}/{video.mp4,metainfo.csv} + Sensors CSV + Audio，强制 IDR 后发 STARTED 0 入队成功；−1 失败（未 init / 已在录）
record_stop() 结束当前段：关 video.mp4（回写 moov）+ metainfo，停传感器 CSV。幂等 0 成功；−1 无活动段
imu_get_latest(&sample) O(1) 读最新 IMU/磁力值缓存（锁保护），填 sxr_imu_sample_t 0 有数据；−1 无数据

record_init 内部默认配置（固定，不可通过 recorder 改）

项默认值
相机stereo（双路）：Camera0 左 + Camera1 右；实际以 HAL 探测的 camera_mask 为准（某 pad 无 sensor 则该路跳过）
分辨率自动探测：HAL 按 pad0/pad2 挂载的 sensor 型号决定 —— SC235HGS = 1600×1200、SC233HGS = 1920×1200
主码流HEVC Main，GOP=30，CBR 4 Mbps，IP-only（无 B 帧）
子码流（预览）自动按主码流 /4：2 Mbps，15 fps（预览尺寸随 sensor，如 400×300 / 480×300；VENC ch1=Cam0 / ch3=Cam1）
IMU / 磁采样率accel 800 Hz、gyro 800 Hz、mag 200 Hz
IQ自动：按 sensor 型号选 sc235hgs_api.bin / sc233hgs_api.bin
音频16 kHz、2 ch、S16_LE（SDK 无音频编码器，PCM fMP4）
时钟ISP 216 MHz、SCL 288 MHz（内部经 /proc 设置）

事件回调 sxr_rec_event_cb_t

typedef enum {
    SXR_REC_EVT_STARTED,       // 两眼首帧 IDR 已写入，录制进行中
    SXR_REC_EVT_IDR_TIMEOUT,   // 强制 IDR 超时(默认 1s) → 自动收尾，无数据
    SXR_REC_EVT_WRITE_ERROR,   // 写失败 → 自动收尾，文件可能不完整
} sxr_rec_evt_t;
typedef void (*sxr_rec_event_cb_t)(sxr_rec_evt_t evt, int error_code, void *userdata);
⚠️

事件回调跑在库内部线程。 必须短小非阻塞；禁止在回调内调 record_* （设 flag 回主循环处理）。错误事件只是撤回并标记本段 STOPPING，record_stop 对已 STOPPING 的段是幂等的，收尾仍由 app 调用。

预览回调 sxr_frame_cb_t（可选）

typedef void (*sxr_frame_cb_t)(int pipe_id, int ch,
    const uint8_t *data, size_t size, int64_t pts_us, int is_sync,
    const uint8_t *csd, size_t csd_size, void *userdata);
  • 收到 子码流编码帧：ch=1（Cam0）、ch=3（Cam1）。预览期常驻、零落盘。
  • 回调在库内部分发线程执行（HAL 取帧线程只入队），但仍是内部线程 —— 须快速返回；队列满时丢最旧帧保最新。
  • 不传 preview_cb 则完全不启子码流取帧。

数据类型 sxr_imu_sample_t

typedef struct {
    double  accel[3];   // m/s², body frame
    double  gyro[3];    // rad/s, body frame
    double  mag[3];     // μT
    int64_t ts_ns;      // CLOCK_MONOTONIC_RAW（与数据集 CSV 的 ts_ns 同域）
} sxr_imu_sample_t;

输出：数据集

每段 record_start(dir) 在 dir 下生成一份完整数据集（视频/元数据/传感器/音频/标定/UTC 映射）， 结构与字段详见 Part II。

✓

使用注意：输出目录务必用 SD 卡（/customer/sd/），/tmp 是 tmpfs，写大文件会 OOM。 同应用可反复 init/start/stop/deinit 多次跑；跨应用（切到参考 demo prog_pipeline）需 adb reboot。

自定义配置：直接用 libsxr_hal

libsxr_recorder 走固定默认参数。要改码率 / GOP / 预览 / 音频 / 时钟等，需绕过 recorder， 直接调用 libsxr_hal：pipeline_create_venc(SxrPipelineConfig*) 建管线 → 自建取帧/传感器， 自己写盘。recorder 加载的 sxr_hal_api_t vtable 如下。

ℹ️

结构体已简化。 SxrPipelineConfig 不再暴露 camera_case / pad / device / iq_path / output_dir：sensor 探测、主码流分辨率、IQ bin 均由 HAL 自动按 pad0/pad2 挂载的 sensor 型号决定（SC235HGS=1600×1200、SC233HGS=1920×1200），结果回填到 camera_mask / width[] / height[] / pts_offset_ns。

配置结构体 SxrPipelineConfig 关键字段

typedef struct SxrPipelineConfig {
    /* 输入（可配置；填 0 用默认） */
    int   isp_clk;             // ISP 时钟 Hz，默认 216M
    int   scl_clk;             // SCL 时钟 Hz，默认 288M
    int   venc_gop;             // 默认 30（IP-only，无 B 帧）
    int   venc_bitrate_bps;     // 单位 bps，默认 4 Mbps
    int   enable_preview;       // 0=关 1=开子码流
    int   preview_width;        // 0=auto -> 主码流/4（按 sensor 型号回填）
    int   preview_height;       // 0=auto -> 主码流/4
    int   preview_bitrate_bps;  // 0=auto -> 2 Mbps
    int   preview_fps;          // 0=auto -> 15
    volatile unsigned char *exit_flag;  // 退出信号
    SxrAudioConfig audio;     // 音频（16k/2ch/S16LE 默认）

    /* [输出] pipeline_create_venc 回填：自动探测 pad0/pad2 挂载的 sensor，
     * 按型号决定主码流分辨率与 IQ bin */
    int   camera_mask;          // bit0=Camera0, bit1=Camera1；0=无 sensor
    int   width[SXR_RECORDER_SNR_MAX];   // 各 camera 主码流宽（探测结果）
    int   height[SXR_RECORDER_SNR_MAX];  // 各 camera 主码流高（探测结果）
    int64_t pts_offset_ns;    // [输出] PTS→MONOTONIC_RAW 偏移（ns）
} SxrPipelineConfig;

另有 SxrRecordConfig（prealloc_bytes / sample_interval_us）、SxrRecordStats （帧数/字节数/丢帧统计）、SxrAudioConfig（增益/采样率）。recorder 已内置全部默认值，自定义时才需直接面对这些类型。

完整调用示例

参考调用方 fmp4_recorder/main.cpp（产物 prog_fmp4_recorder，独立测试工具）：预览整场会话，循环录 N 段， 再读 IMU，仅使用 libsxr_recorder 公开 API。系统默认运行的 prog_sxrservice （sdk/verify/sample_code/demo/sxrservice）经 recorder_bridge.c 以同样方式调用 recorder，另叠加 BLE/WiFi/WS 预览等业务。

#include "sxr_recorder.h"

static volatile unsigned char g_bExit = 0;
static volatile unsigned char g_recStarted = 0;
static void sig_handler(int sig){ (void)sig; g_bExit = 1; }

/* 预览回调：子码流 ch1/ch3 编码帧，跑在库内线程，须快速返回 */
static void preview_cb(int pipe_id, int ch, const uint8_t *data, size_t size,
                         int64_t pts_us, int is_sync,
                         const uint8_t *csd, size_t csd_size, void *ud)
{ /* 转发到 WS / 显示等 */ (void)pipe_id;(void)ch;(void)data;(void)size;(void)is_sync;(void)csd;(void)csd_size;(void)ud; }

/* 录制段事件回调：只设 flag，勿调 record_* */
static void evt_cb(sxr_rec_evt_t evt, int err, void *ud) {
    (void)ud;
    if (evt == SXR_REC_EVT_STARTED) g_recStarted = 1;
    else { printf("record event err=%d\n", err); g_bExit = 1; }
}

int main(int argc, char **argv) {
    signal(SIGINT, sig_handler); signal(SIGTERM, sig_handler);

    /* ① 加载 libsxr_recorder.so（dlopen + vtable，找不到返回 NULL） */
    const sxr_recorder_api_t *REC = sxr_recorder_api();
    if (!REC) { fprintf(stderr, "load libsxr_recorder.so failed\n"); return -1; }

    /* ② 初始化（默认 stereo + IMU + 音频；分辨率按 sensor 自动探测；给 preview_cb 则开预览） */
    if (REC->record_init(preview_cb, NULL) != 0) { fprintf(stderr, "record_init failed\n"); return -1; }
    sleep(2);   // 等 AE/AWB 收敛、管线就绪

    /* ③ 录 N 段，每段独立 clip_NNN/ 目录 */
    for (int seg = 1; seg <= segs && !g_bExit; seg++) {
        char dir[640];
        snprintf(dir, sizeof dir, "/customer/sd/fmp4_recorder/clip_%03d", seg);
        g_recStarted = 0;
        if (REC->record_start(dir, evt_cb, NULL) != 0) break;  // 异步
        while (!g_recStarted && !g_bExit) usleep(20000);        // 等 STARTED
        sleep(segdur);                                    // 录制
        REC->record_stop();                                     // 收尾本段（回写 moov）
    }

    /* ④ 读 IMU 最新值（可选，O(1)） */
    sxr_imu_sample_t s;
    if (REC->imu_get_latest(&s) == 0)
        printf("a=(%.2f,%.2f,%.2f) g=(%.2f,%.2f,%.2f) m=(%.1f,%.1f,%.1f) ts=%lld\n",
               s.accel[0], s.accel[1], s.accel[2],
               s.gyro[0], s.gyro[1], s.gyro[2],
               s.mag[0], s.mag[1], s.mag[2], (long long)s.ts_ns);

    /* ⑤ 收尾（幂等；即使漏了 record_stop 也会 finalize） */
    REC->record_deinit();
    return 0;
}

Part II · 数据集结构与格式

录制数据集

录制产物（clip_NNN/）的文件结构与字段语义 —— 视频 / 传感器 / 音频 / UTC 映射 / 标定 / 对齐换算。

概述

ℹ️

关键事实：所有数据流（视频曝光、加速度/陀螺/磁力、音频）的时间戳都统一在 CLOCK_MONOTONIC_RAW 纳秒域 —— 不是墙钟时间，不能直接 date -d @ts。 要恢复 UTC，用 sensor_time_to_utc.csv 换算。

录制参数（默认）值
视频分辨率1600 × 1200
视频编码HEVC (H.265) Main，IP-only（无 B 帧），GOP=30，CBR 4 Mbps
子码流（预览，不入数据集）400 × 300，2 Mbps，15 fps
加速度 / 陀螺 / 磁力 采样率800 / 800 / 200 Hz
音频16 kHz，2 ch，S16_LE

目录结构

每个片段一个 clip_NNN/（NNN 从 001 起，三位补零）。双目为 Camera0（左眼）+ Camera1（右眼）。

<output>/                         # 默认 /customer/sd/fmp4_recorder
└── clip_001/                      # 一次录制片段的产物
    ├── id.txt                     # 硬件 UUID（纯文本）
    ├── sensor_time_to_utc.csv      # MONOTONIC_RAW → UTC 映射（周期采样）
    ├── Camera0/                     # 左眼
    │   ├── video.mp4                # HEVC fMP4
    │   ├── metainfo.csv             # 每帧曝光元数据
    │   └── camera_params.json       # 内参 + 外参
    ├── Camera1/                     # 右眼（结构同 Camera0）
    │   ├── video.mp4
    │   ├── metainfo.csv
    │   └── camera_params.json
    ├── Sensors/
    │   ├── accel.csv              # 加速度
    │   ├── gyro.csv               # 陀螺
    │   ├── mag.csv                # 磁力计
    │   └── imu_calibration.json  # IMU 标定
    └── Audio/                      # 可选：无麦克风则整个目录不生成
        ├── audio.mp4              # PCM fMP4
        └── metainfo.csv
ℹ️

每个 clip_NNN/ 是一次完整、独立的录制片段，目录内文件自洽，片段之间互不影响。

时间基准

整条数据链统一 CLOCK_MONOTONIC_RAW（纳秒），自上电起单调递增、不受 NTP 调整影响。视频 / accel / gyro / mag / 音频同域，因此天然对齐，无需跨域偏移。

畸变模型详解（radialDistortion）

该字段描述镜头几何畸变。设备标定声明模型为 FISHEYE_4_PARAMETERS —— 一个 4 参数鱼眼径向畸变模型。8 元素数组中只有前 4 个有效，其余为 0（无切向畸变项）。

下标来源含义
[0..3] = k1, k2, k3, k4标定给出的 4 个系数鱼眼畸变系数（仅这 4 个有效）
[4..5]预留槽位恒为 0，未使用
[6..7]补齐填充恒为 0，凑成 8 元素，未使用

基本模型：理想针孔投影得归一化像坐标 (x, y)，到主点半径 r = √(x² + y²)，对应入射光与光轴夹角 θ = atan(r)。鱼眼镜头对大角度入射光弯曲强烈，用系数修正 θ（半径）的映射。4 参数鱼眼模型典型采用 Kannala-Brandt 形式：

θ_d = θ · (1 + k1·θ² + k2·θ⁴ + k3·θ⁶ + k4·θ⁸)

# θ   = atan(r)          归一化半径对应的入射角（针孔/等距投影下）
# θ_d                    畸变后的等效角度 → 投到像面得实际像素位置
# k1..k4                  4 个畸变系数（radialDistortion[0..3]）

参数意义：

  • k1：主项，决定整体径向弯曲的方向与量级；通常 |k1| 远大于高阶项。
  • k2, k3, k4：高阶修正项，主要影响大角度（画面边缘）区域。
  • 系数绝对值越小，越接近理想针孔/等距投影；本设备系数量级约 1e-3 ~ 1e-2。
ℹ️

畸变系数为设备出厂标定值，本数据集原样透传，不做去畸变。下游需按 FISHEYE_4_PARAMETERS 模型应用 k1..k4；上式为 4 参数鱼眼模型的典型（Kannala-Brandt）形式，厂家精确多项式约定以其标定规范为准。

nonorthogonality 的使用

先明确：CSV 里的值是否已校正？数据集的 accel.csv / gyro.csv 只经过了 FSR 量程标定 + 安装方向矩阵（芯片坐标 → body 坐标），并未应用 imu_calibration.json 中的 bias / scale_factor / nonorthogonality。这三项是设备出厂精标参数，留给下游按需应用。

nonorthogonality 修正什么：IMU 三轴因制造公差并非严格正交（夹角 ≠ 90°），导致轴间串扰——某轴的真实加速度/角速度会少量泄漏到另外两轴。这组参数即用于消除该耦合；值越接近 0，正交性越好。

使用方式：读出 CSV 值后，按 bias → scale → nonorth 的顺序校正，最后一步用 nonorthogonality 构成的 3×3 矩阵做轴间去耦：

v_true ≈ N⁻¹ · ( (v_csv − bias) ⊘ scale )      # ⊘ 逐元素相除

# 典型的 3 参数 → 3×3 非正交耦合矩阵（下三角，小角近似）：
N = ⎡ 1       0       0    ⎤
    ⎢ n_yx    1       0    ⎥
    ⎣ n_zx    n_zy    1    ⎦
# n_yx：y 轴相对 x 轴的偏角，以此类推。也可能用 skew（反对称）形式。
  • 顺序：先去偏（bias）、再标定灵敏度（scale）、最后轴间去耦（nonorth）。
  • accel / gyro 各自一组：nonorthogonality.accelerometer 与 .gyroscope 互相独立，分别用于两路。
  • 量级与取舍：三项校正中通常 bias 影响最大、scale 次之、nonorth 最小。一般姿态/记录类应用可忽略 nonorth；高精度 VIO / SLAM 建议应用。
⚠️

本数据集原样透传出厂标定值、未应用上述任何校正。3 参数到 3×3 矩阵的精确形式（下三角 / skew、乘 N 还是 N⁻¹、scale 作乘子还是除子）以设备标定规范（tracking 组）为准，使用前请与厂家约定核对。

时间映射（sensor_time_to_utc.csv）

把传感器时间（MONOTONIC_RAW）映射到 UTC（CLOCK_REALTIME）的侧车文件。数据流仍是裸 MONOTONIC_RAW，本文件是唯一墙钟桥梁。

ℹ️

为什么周期采样而非单点：设备 UTC 可能被 NTP/手动校准（尤其开机后 NTP step），单点 offset 在校准后就过期。周期采样（~1 Hz）让下游对相邻行插值即可跟踪跳变，offset_ns 列直接显示跳变。

# utc(t) for sensor_time t: linear interpolation between adjacent rows

# target period = 1.000 s (actual cadence may vary slightly)

列单位说明
sensor_time_nsns · MONOTONIC_RAW采样瞬时的传感器时间。

时间对齐与换算

1. 传感器时间 → UTC

给定任意 sensor_time（MONOTONIC_RAW ns），在 sensor_time_to_utc.csv 中找包围它的两行 (s₀,u₀)、(s₁,u₁)，线性插值：

utc(sensor_time) = u₀ + (u₁ − u₀) × (sensor_time − s₀) / (s₁ − s₀)

UTC 未被校准时（offset_ns 恒定），等价于 utc = sensor_time + offset_ns。

2. 视频 ↔ metainfo 配对

mp4 样本的 PTS（µs）= metainfo 行的 pts_us。要拿某帧的绝对曝光时间，先按 pts_us 找到 metainfo 行，取其 exposure_start_ns（MONOTONIC_RAW），再按上一步换算 UTC。

3. 跨流对齐

视频 exposure_start_ns、IMU/磁力 ts_ns、音频 ts_ns 同属 MONOTONIC_RAW，可直接相减求时差；立体配对用两路 exposure_start_ns 最近邻（首帧已对齐到同一次物理曝光）。
